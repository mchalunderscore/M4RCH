# Native PM host-pointer consumers and candidate mapping propagation

Actual bounded native consumer windows establish that3D host descriptor910/938 and TA1228/1250 are passed as scheduler slot2d8 arguments (host_pointer,0). The returned translation is stored in output structures at3D30/38 and TA28/30 respectively. These output objects are not yet class-qualified as final firmware work records. TA1230 is CPU-dereferenced by the following preparation window: modes1and2 write PM228 to scene+4c; modes0and3 skip it. Thus blindly changing the host descriptor pointers into device/FW addresses would break a real host access. A Linux translation layer must preserve the distinction and qualify the final consumer/output layout.

The new audit-native-pm-address-consumers.py runs all four translation windows512 times each with distinct randomized host inputs and supplied translation outputs. Exact call arguments, complete output bytes and unchanged input descriptor checked. The scene window runs512 times covering four modes128 times each, with full128-byte scene and unchanged descriptor comparisons. PAC bypassed and the translation service remains supplied. This qualifies bounded windows, not complete serialization or the actual translator implementation.

The PM exporter also accepts --mapping-candidates JSON (hw_state,hw_counter,reset_first,reset_translated,page_list,discard,scene). Case0 can now supply consistent page-aligned candidates to the native HWPB reset and concrete scene setup while all256 initialized-retention chains retain full independent byte checks. Candidate layout in out/native-pm-address-domains: six manager/state fields match supplied values, all16 scene+28 fields match the scene candidate, and packed ring0 has the expected native address projection. Service domain/class semantics, first-map translation and actual aliases remain unproved; equal first/translated candidate values are a supplied fixture, not evidence of identity translation.

The remaining CPU map50/map60 values, vectors and inherited fields remain emulation identities or randomized inputs. Do not publish snapshots.
