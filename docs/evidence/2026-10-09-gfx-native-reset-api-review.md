## Command ordering and errors

Every new command is a forced full-word regmap_write, including policy and cleanup commands. A qualified pre-inhibit image provides bounded fallback after failed fresh reads; successful AUTO inhibition supplies the fresh preserved image. Disable writes B|DEV_DISABLE and receives a requested1us delay even after a write error. Its bounded poll checks ACTUAL/TARGET active, AUTO/PS_RESET/BUSY/RESET clear, while allowing DEV_DISABLE readback to be either state. Assertion writes B|DEV_DISABLE|RESET explicitly, then delays1us on both success and uncertain-error paths. Its raw read is diagnostic; neither command bit must read set. Release forcibly writes B even when observed command bits already read clear.

A release write must report success and compatible inhibited power/clear-state reads must pass before policy restoration. Original AUTO may then gate ACTUAL. Each poll has at most101 reads and100us requested delay. This is an experimental power/BUSY policy stricter than the unqualified native policy, and combined preserved-image commands differ from the generic Linux RMW sequence. No byte-for-byte native equivalence, physical pulse width or reset coverage is claimed. The harness's aggregate delay assertion is a bound on its tested models; six polls are structurally possible, and bus operations themselves do not supply a wall-clock bound.

All failures after first inhibition enter forced cleanup, which writes an inhibited release image twice irrespective of prior bus errors. An errored release remains uncertain even if a subsequent diagnostic sample looks compatible; AUTO restoration is then withheld. A successful later release/check may allow restoration while preserving an earlier cleanup error. Restore-write errors remain visible and do not become policy-restored claims merely because a later diagnostic sample matches. Primary and cleanup errors remain distinct, with no reset assertion retry.

## Observation and verification

Attempt bits precede each write call. Desired entries hold full command words; write-error slots have meaning only for attempted commands. Successful raw read values, per-stage attempts/count/last bus error and poll delays remain separate. Timeout may have read_error0 while overall operation/cleanup reports-ETIMEDOUT. Common valid bits describe a successful sample, including an earlier sample retained after a later failure. Cleanup release/final stages share common.cleanup_final, so that value requires the new read-stage provenance to interpret.

release_command_verified describes successful release command/checks, without confirming physical release of an unobservable line. sequence_completed describes the primary sequence and policy checks. Neither means that ASC/GPU/UAT/DMA stopped accessing memory.

The reviewer independently reproduced all396 actual-C ASan/UBSan cases across nine separate bit10/bit31 models: latched, nonlatched readback and self-clearing. Coverage includes both AUTO policies, primary read/write failures, committed-error writes, forced cleanup, persistent errors, policy/status timeouts, preserved earlier sample values, delays on uncertain assertion and lock balance. These use recording CPU models; real DT/provider behavior, kernel locking races, MMIO semantics, timing, reset scope and physical DMA cessation are excluded. Full kernel and corrected USB artifact closure require separate qualification.
