# Native shutdown enclosure after v20 boot09

The Fender disable leaf is verified, but graceful GPU shutdown is still missing as a completion boundary. Boot09 wrote `0→4`, then completed native PMP/PMC OFF coordination and one PM put; all101 physical samples were `0x0f000b00`, with BUSY=`0x800`. The normal `202` ACK timed out, so ASC idle came from the one-shot NMI route. Raw target/completion/queue captures and the pending-bit28 trace tail remain identical to v19. None of this identifies a single missing register or a live wait PC.

The matched driver has separate GPU and ASC lifecycle scopes. Native idle gating checks the device-control queue898 cursor pair at `897580c`, then host cold-boot done at `8975838/3c`, before asking its payload provider for state2 at `8975890`. The separate GPU control helper `89c8860` builds opcode`0a` followed by a u32 boolean and conditionally waits for device-control completion. Native `waitForFirmwarePowerOff` at `89bf120` checks a distinct32-byte block at host888, offset10; its generation is at1c. These are not the large main471 power object and are not proved by ASC status idle. The existing Oct8 lifecycle evidence already identified them; current v20 makes the missing boundary more useful to test.

Fender’s larger enclosure also has object state that the leaf transfer omits: firmware+1660 is initialized1 and only a decrement from1 invokes the Common callback; Fender+8 caches the enabled state. The Common OFF leaf at `89d8758` precedes conditional provider power(false,null,index0) at `89d87a0` and clock(false,index0) at `89d87e4`. Those calls require the shared probe’s held-vote flag at `c6e7917`; acquisition also depends on policy at `c6e7919`. Boot09 SGX gates are400/402 and ASC gates401. Virtual400/401 feed GFX386, but they have no independent physical PS words. The actual shared provider/held policy is unobserved, so duplicate GFX writes or invented extra native votes are not justified. The omitted ON accelerator slotd20 resolves to a perf-counter no-op, closing that alternative.

The ASC framework path additionally stops CPU, unmaps only its optional firmware object, conditionally invokes mapper `setActive(false)`, and drops provider clock votes. The mapper’s dynamic IOResources target remains unobserved. Native PMP/PMC ordering is already integrated. Native target0 explicitly expects ACTUAL0 and conditionally waits BUSY0; the driver supplies no BUSY waiver. Earlier v9 no-work shutdowns repeatedly reached strict `0x0f000300` after a normal202 ACK without the later Fender leaf transfer. That points toward incomplete GPU work or firmware lifecycle completion, while leaving causality open.

One coherent future experiment is a **single bounded GPU graceful control before normal202**, preserving the selected v21. First bind opcode0a’s native bool/caller and firmware handler, exact ring entry/completion ABI, and owned addresses for the distinct888 block. Then one publication can record command consumption/completion, shared power completion,202 ACK, CPUstop, current Fender/PMP/PMC/OFF and strict BUSYclear separately. Retain the owner on any failed boundary; add no guessed reset or shared-state zeroing. Opcode0a may configure idle policy rather than force immediate OFF, so its meaning is an essential input, not a reason to copy the record blindly.
