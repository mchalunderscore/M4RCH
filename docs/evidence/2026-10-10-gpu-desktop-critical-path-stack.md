# GPU desktop: existing stack and critical path

Reuse Gravity Linux and Gravity Mesa. The project already has the Linux graphics interfaces and userspace rendering stack; the missing work is a T6040/G16S hardware port and presentation integration. Start adapting those existing paths alongside the firmware execution proof rather than waiting for every standalone power-management experiment to finish.

**Existing code:** the [native-reset DRM frontend](/home/alice/Desktop/m4rch/out/gfx-native-reset-kernel/linux/drivers/gpu/drm/asahi/g16_drm.rs:148) implements render-node registration, GEM/VM/queues/submit, syncobj timelines, DMA fences, scheduling and ordinary-buffer PRIME export. Existing G16 TA/fragment and VM backends and Mesa Apple9/Gallium/GBM/EGL code are reusable. A [saved build receipt](/home/alice/Desktop/m4rch/docs/evidence/2026-10-06-gpu-native-build.json) records successful offline builds; private-prefix libraries exist. These are implementation/build facts, not hardware-rendering proof.

**Concrete integration blockers:** [T6040 normal startup is refused](/home/alice/Desktop/m4rch/out/gfx-native-reset-kernel/linux/drivers/gpu/drm/asahi/asahi_m4.rs:66), probe-only creates no DRM device, and [GET_PARAMS still reports G/0x8132/one cluster](/home/alice/Desktop/m4rch/out/gfx-native-reset-kernel/linux/drivers/gpu/drm/asahi/g16_drm.rs:432). The platform builders retain donor assumptions. [Mesa recognizes G16S but rejects it](/home/alice/Desktop/m4rch/out/gpu-native-20261006/mesa-full/src/asahi/lib/agx_device.c:762); its Apple9 rendering/entry setup excludes G16S. Merely lifting the rejection gates is not a port. The Apple AGX binary supplies ABI/lifecycle evidence; Gravity DRM and Mesa supply the reusable Linux implementation.

The headless-render critical path is:

1. Establish firmware application control consumption and idle, then submit one owned TA/3D job with actual completion and correct pixel readback. The [saved v11 management result](/home/alice/Desktop/m4rch/docs/evidence/2026-10-10-gfx-native-ap-retained-cycle-live-native-boundary.md:3) has application rejoin 0 and failed initial class86 recovery; more management restarts do not establish execution.
2. Transfer the proven startup/initdata/power/application contract into Gravity's normal backend, with truthful T6040 topology/resources and its existing DRM submission/fence interfaces. This adaptation can begin offline now.
3. Qualify G16S graphics/shader-entry/resource layouts in the existing Mesa path, then demonstrate repeated headless EGL/GBM rendering, textures/blits and synchronization. One triangle is the first hardware milestone, not the whole compositor workload.

Desktop presentation is a separate integration step: buffer export/import, formats/modifiers, fences and compositor device selection must work. Both static KWin service overrides currently set `KWIN_COMPOSE=Q`; the greeter separately forces software rendering. Hardware-session validation must address those settings after EGL/GBM works.

The [2026-10-07 display baseline](/home/alice/Desktop/m4rch/docs/dcp001-preparation.md:3) found no DCP/DISP/crossbar/panel DT nodes and only simpledrm. The inspected native-reset config disables DRM_APPLE and enables simpledrm. DCP code already has an IOMFB26.6 path, but explicit T8132/26.6.2 gating and missing T6040 topology/providers/stream identities/reservations still block native display takeover. This historical capture is not a new live DT inventory.

An interim copy-backed presentation path is an **untested hypothesis**: [simpledrm performs CPU-access damage blits](/home/alice/Desktop/m4rch/out/gfx-native-reset-kernel/linux/drivers/gpu/drm/sysfb/drm_sysfb_modeset.c:329), so offscreen GPU output might be copied/read back into that existing path. Actual compositor/GBM/EGL device selection, import or copy support, mappable formats/modifiers, fencing, conversion and copy performance must be demonstrated. PRIME export alone does not prove it will work. Native DCP takeover is unnecessary for the first headless render and can proceed independently.

For the fastest initial vertical slice, prioritize application execution, the existing DRM/Mesa port and one viable presentation path. Full unload/backing retirement, suspend/resume, power tuning, additional management-only epochs, native DCP, compute and Vulkan need not all precede headless graphics. Keep ownership, bounded submission, completion and backing lifetime correct; a persistently powered prototype can defer advanced PM.

This review changed no code/configuration, ran no builds/tests, and performed no live hardware reads or controls. The companion JSON freezes 19 local source/document/configuration pins and distinguishes existing implementation, historical observations and untested presentation inference.
