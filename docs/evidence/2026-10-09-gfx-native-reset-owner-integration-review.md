# Native command owner and receipt integration: independent offline review

The version-2 integration has no source-control blocker. This review reads the actual contract, preparer, owner C, startup guard and resident/root wrappers; it does not run a kernel module or access hardware. The current stopped owner on boot `ce6572c9-2491-4c87-8e27-6e82cc0ac657` remains untouched.

The receipt selects the exact native command contract, `7.1.13-m4rch-gpu-native-reset`, frozen native patch/source/header, legacy checked API patch and promoted DWC3 role patch. Unknown or incomplete profiles refuse admission. Kernel validation retains the maintained-source baseline and allows only the reviewed native PMGR source and promoted DWC3 source exceptions; configuration differs only in the release suffix. It also validates compiled artifacts, extracted kernel notes and all three GPL API exports. Compiled artifact closure is separately pending the full build.

The preparer copies the preserved graph/backing, adds both the existing scope feature and native sequence macro, and recompiles all eight helpers. It retains the mandatory nonresident allocation-only gate-1 shadow followed by gate-2 resident publication. Actual C startup admission remains unchanged: no shutdown, warm restart or release; the feature compile guard excludes startup work. The receipt forces power retirement, backing release and work submission false, with all 174 pages retained. Root admission rejects arena/non-graph, warm restart and lifecycle cycles before hardware access.

The owner keeps the graph lock and consumed-control/empty-work/empty-active-TA guards. An explicit command permanently seals the owner even when a precondition refuses entry. The attempted bit is set before API entry, and the host receive worker cannot drain or publish after the seal. Userspace persists the attempt and uncertain-outcome seal before opening/writing sysfs. Success or failure does not authorize a second reset, restart, submission, context reuse, unmap, free, PM put or unload. Diagnostic sample/snapshot and idempotent packet-free host stop remain available.

The native logger records command attempts separately from forced desired full-register words and each write result. It records read-stage attempts/counts/delays and bus errors separately from common valid raw values; this preserves the documented last-successful-sample semantics of shared cleanup-final storage. It expressly logs physical reset acknowledgment and retirement as false. API return zero is rejected with EIO unless sequence completion, release command verification, restored AUTO policy and disable/assert/release attempts are present. Common operation/cleanup errors are also preserved. This acceptance checks command evidence only; it cannot prove physical reset coverage or DMA cessation.

The existing root validation reports are bound to the current sources by independent SHA checks: 517 native actual-C owner RAM replay cases (including four inconsistent-success metadata refusals) and 54 userspace wrapper checks. The owner replay uses recording API/MMIO/PM/transport stubs and replaces only unreachable submit cache assembly. The wrapper uses fake regular-file sysfs. These reports establish admission/sealing/logging behavior, not real concurrency, provider lifetime, hardware timing, reset coverage or retirement. No old hardware trial was repeated.
