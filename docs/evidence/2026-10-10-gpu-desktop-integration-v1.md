# Gravity integration implementation: staged v1

The [tracked kit](/home/alice/Desktop/m4rch/experiments/t6040-gpu/desktop-integration/README.md) and [selected source receipt](/home/alice/Desktop/m4rch/out/gpu-desktop-integration-v1/selected-source-receipt.json) are ready for isolated module/Mesa integration. Frozen baseline trees are unchanged.

The Linux patch carries the selected chip profile through probe → DRM → bootstrap → platform and reports the runtime-bound chip, variant, clusters, logical slots and explicit masks through GET_PARAMS. A pure topology helper supports T6040's two clusters/ten slots, with captured J614s masks `3db/3db` giving 16 enabled cores. It does not fill missing inputs from that capture. An explicit T8132-only initialization selector prevents a metadata flag from authorizing donor builders. T6040 normal startup remains closed.

The Mesa patch checks chip/topology/masks immediately after GET_PARAMS and moves the unqualified G16S rejection before VM creation. It preserves the unresolved firmware/packet gate. Neither patch guesses shader or firmware command fields.

[Offline qualification v2](/home/alice/Desktop/m4rch/out/gpu-desktop-integration-v1/qualification-v2/qualification.json) passed six actual Rust profile tests, 5,194 actual Mesa-header assertions and 22 synthetic pixel/renderer acceptance assertions. It covers all 1,023 valid one-cluster masks, crossed identities, missing/empty/high/trailing masks, captured J614s identity, unchanged frozen inputs and exact fresh patch replay. Actual Rust and C outputs agree on `16/6040/S/1 die/2 clusters/10 logical slots/16 enabled/3db/3db`. ASan/UBSan passed; unsupported LeakSanitizer thread inspection is disabled for these heap-free pure tests. The original environment failure and its 11 input snapshots remain in qualification v1.

The linked [headless harness](/home/alice/Desktop/m4rch/experiments/t6040-gpu/desktop-integration/headless-smoke.c) requires an explicit Asahi render node, complete captured T6040/B1 identity, a GBM-bound hardware Apple M4 Pro/G16S GLES3 context, and two completed draws with fresh full RGBA8 readback. Triangle color changes red → green over blue; bounded completion and pixel criteria reject stale or software-only results. Native EGL fence export is tested when available and reported separately. Exclusive captures preserve previous evidence. The harness was **not executed**; a future hardware run must bind the loaded kernel/Mesa and environment, excluding shim/preload substitution.

Remaining work is the real T6040 startup/power/application/completion contract and boot input binding; G16S firmware scene, tiling/resource and Apple9 graphics/shader-entry layouts; isolated module/Mesa compilation; then actual headless rendering. Root can target-compile the five changed Asahi Rust files without a full kernel build. Desktop buffer import/formats/modifiers/fences/compositor selection and DCP remain separate integration work.

No hardware reads/controls, full kernel/Mesa builds, installation or system desktop/GRUB changes were performed. The companion JSON pins 17 handoff inputs; the selected qualification separately binds 27 inputs and all staged source identity.
