# Reproducing the current J614s setup

The [Aurora ALARM fork](https://github.com/mchalunderscore/alarm-aurora/tree/j614s/full) supplies source-based PKGBUILDs pinned to the J614s component forks. The installed kernel, Aura and U-Boot have been built from those recipes and booted together in a one-shot trial. The running kernel is `7.3.0-1-14-ARCH`; GRUB now defaults to the forked kernel. This inventory is not an unattended installation procedure; see [status](status.md) and [recovery](recovery.md).

| Component | Source or input required | Reproduction boundary |
| --- | --- | --- |
| macOS installer and firmware extraction | [Installer fork](https://github.com/mchalunderscore/aurora-installer) and the machine's own firmware | The Wi-Fi extraction candidate is unqualified on macOS and does not automatically select a Recovery image with complete firmware. The earlier installer used older boot artifacts and does not automatically reproduce the current fork-based installation. This machine's firmware, calibration, SEP identity and keybag are private and cannot be reconstructed from this repository. |
| Running and next-boot kernel | Aurora ALARM fork `j614s/full` and its pinned Linux source | Build with `makepkg -si`; the installed forked kernel booted in the one-shot trial. The previous kernel and modules are retained in the recovery archive. |
| Aura and U-Boot | Aurora ALARM fork `j614s/full` and its pinned component source forks | Build with `makepkg -si`; stage one is unchanged and the updated stage two booted in the one-shot trial. |
| Board configuration and stage two | Installed Aura, U-Boot and Linux packages and Aurora shared boot hooks | No J614s-specific package is installed. The standard updater assembles stage two from kernel-owned DTBs and the installed loader packages. Host-local GRUB preferences, disk UUIDs, ESP and private firmware remain machine-specific. See [recovery](recovery.md). |
| Mesa, microphone and UCM | The Aurora ALARM fork and its pinned component source forks | The native Mesa split packages and audio/UCM were installed with `makepkg -si`. Mesa passed its recipe tests and a live Zink surface-reuse check; FEX guest and Flatpak extensions remain separate. |
| Touch ID and other Aurora packages | Signed Aurora packages, machine-owned calibration and identity state | The installed SEP and fingerprint packages are stock Aurora packages, not the retired local recipes. Preserve identity and recovery data independently. Consult `/usr/share/doc/aurora-sep/` on the installed system. |
| Graphical privilege authorization | `run0`, Noctalia's polkit agent and the separate Home Manager configuration | The user's zsh aliases `sudo` to `run0`. Programs invoking sudo directly use the system fingerprint and password PAM stack. |
| Steam and GE-Proton | The separate Nix/Home Manager flake in `/home/michal/Projects/flake` | Its `pkgs/steam-arm64` and `pkgs/ge-proton-arm64` definitions and their own source inputs reproduce that separate configuration. This repository's retired Steam and Proton recipes described a different installation. |

The networkd wait-online condition under `/etc/systemd/system/systemd-networkd-wait-online.service.d/10-require-wired.conf` is a machine-local setting and is not part of the J614s platform package.

The [historical package recipes and source records](https://github.com/mchalunderscore/M4RCH/tree/99a6c07/packages) are in Git history and do not build the current stack. The active upstream-submission and hardware investigation files preserve test and review context, not required install inputs. Unique trial evidence and build provenance are retained at `/home/michal/.local/share/m4rch-archive/cleanup-20261102/`; duplicate source and build trees were removed; generated artifacts and external `/var/lib/m4rch` recovery files are intentionally outside the source inventory; Git history does not preserve these machine-local inputs.
